# Plan: Tier 1 — Critical/High Security Remediation

## Created
2026-06-10

## Status
completed

## Objective
Close the six Critical/High security findings from the framework audit: SQL injection in the query builders (F1), rate-limiter bypass / global DoS / non-atomic increment (F2), LFI/RCE in the translation file loader (F3), mail header (CRLF) injection (F4), broken access control where `#[RequiresPermission]` is never enforced (F5), and PHP object injection via bare `unserialize()` of queue/cache payloads (F6).

none

## Discovery Notes

### Finding-by-finding: new work vs. overlap with existing plans
Phase-1 confirmed against source. Every finding is **new security-hardening work** layered on top of feature plans that are already implemented (most are `completed`). None of the existing plans address these vulnerabilities.

- **F1 (SQLi)** — Overlaps the package and `IdentifierValidator` introduced by `plans/query-builder-raw-select-where/`, but that plan only hardened the *raw* escape hatches (`selectRaw`/`whereRaw`/`orderByRaw`) via `IdentifierValidator::assertNoDangerousPatterns()` (a denylist). F1 is the orthogonal, **larger** hole: the *non-raw* methods (`where`/`orWhere`/`whereIn`/`whereNull`/`whereNotNull`/`join`/`leftJoin`/`rightJoin`/`orderBy`/`table`/`count`/`insert`/`update` keys) never validate identifiers, the stored comparison operator is emitted verbatim with no allowlist, and `quoteIdentifier()` does not escape an embedded delimiter. This plan **extends** the same `IdentifierValidator` with an operator allowlist + delimiter-escaping helper and routes the non-raw methods through it. We do NOT touch the raw escape hatches.
- **F2 (rate limiter)** — `plans/rate-limiting/` built the package as feature work and explicitly listed "Redis-specific optimizations" as out of scope; it never addressed proxy spoofing or atomicity. New work.
- **F3 (translation LFI)** — `plans/translation/` built the loader; no path sanitization was ever in scope. New work.
- **F4 (mail CRLF)** — `plans/mail-package/` defined `Address` with `FILTER_VALIDATE_EMAIL` on the email only; the display name and custom headers were never validated. New work.
- **F5 (broken access control)** — `plans/admin-system/` task 010 created `AdminAuthMiddleware` + `RequiresPermission` but wired the permission branch behind constructor params (`?string $controller`, `?string $action`) that the routing pipeline never populates, leaving it dead. New work that fixes the wiring (touches `marko/routing` + `marko/admin-auth`).
- **F6 (object injection)** — No existing plan. New work.

### Verified source facts (line numbers confirmed Phase 1)
- `IdentifierValidator` lives at `packages/database/src/Query/IdentifierValidator.php`. Public API today: `parseSelectExpression()`, `isValidIdentifier()` (pattern `/^[a-zA-Z_][a-zA-Z0-9_]*$/`), `assertNoDangerousPatterns()` (denylist for `;`, `--`, `/*`, `*/`, backtick). `InvalidColumnException` (`packages/database/src/Exceptions/`) has `invalidColumn()` / `invalidAlias()` factories.
- mysql `quoteIdentifier()` at `MySqlQueryBuilder.php:569`; pgsql at `PgSqlQueryBuilder.php:573`. Both split on `.` and wrap each part in backtick / double-quote with **no delimiter escaping**.
- `where()` mysql:192 / pgsql:191; `orWhere()` mysql:269 / pgsql:268; operator emitted verbatim in `buildWhereClause()` (mysql:805 / pgsql:803) as `sprintf('%s %s ?', $columnExpr, $where['operator'])`. Joins emit `$join['operator']` verbatim too.
- `RateLimitMiddleware::resolveKey()` returns `$request->header('X-Forwarded-For') ?? $request->header('Remote-Addr') ?? 'unknown'`. `Request` (`packages/routing/src/Http/Request.php`) is `readonly`, holds `private array $server`, and `header()` only reads `HTTP_*` keys (so `header('Remote-Addr')` always misses → everything collapses to the `'unknown'` global bucket). No `ip()`/`server()` accessor exists. `RateLimiter::attempt()` is a non-atomic `get → compare → set`. `CacheInterface` has no `increment()`.
- `FileTranslationLoader::resolveFilePath()` interpolates `$locale`/`$group`/`$namespace` straight into a path that `load()` then `require`s — both the namespaced and non-namespaced branches. `TranslationException` is currently an empty `MarkoException` subclass (no factories).
- `Address::toString()` emits `$this->name` raw (`"$name <$email>"`). `Message::header()` (mail/Message.php:159) stores arbitrary name/value into `$headers`. `SmtpMailer::buildHeaders()` writes From/To/Cc/Reply-To via `Address::toString()` raw, custom headers as `"$name: $value"` raw, and only the Subject through `encodeHeader()` (RFC-2047 B-encoding, SmtpMailer.php:406).
- `MiddlewarePipeline::process()` resolves middleware with `$this->container->get($middlewareClass)`; the container fills the `?string $controller`/`?string $action` params with `null` (builtin-with-default path, `Container.php:181`), so `AdminAuthMiddleware::getRequiredPermission()` (admin-auth `:117-123`) always returns `null`. `Router::handle()` has `$matched->route->controller` / `->action` in scope when it builds the handler closure and the middleware list.
- Bare `unserialize()` confirmed at: `cache-file/.../FileCacheDriver.php:253`; `cache-redis/.../RedisCacheDriver.php:37,120`; `page-cache-file/.../FilePageCacheDriver.php:42,132,249`; `queue/src/AsyncObserverJob.php:17`; `queue/src/Job.php:34` (`Job::unserialize`, paired with `Job::serialize` at :26-28 = `serialize($this)`); `queue/src/Command/RetryCommand.php:64,89`; `queue/src/Command/FailedCommand.php:73`. **CORRECTED (was a drift error):** the broker drivers DO unserialize directly — `queue-database/DatabaseQueue.php:120` (`unserialize($row['payload'])`) and `queue-rabbitmq/RabbitmqQueue.php:120` (`unserialize($message->getBody())`) BOTH call bare `unserialize()` on the stored output of `Job::serialize()`; they do NOT route through `Job::unserialize()`. These are the two highest-traffic object-injection sinks and they MUST be hardened in Tier 1, otherwise F6 is not closed for the database/rabbitmq queues. Consequently the envelope cannot live solely inside `Job::serialize()`/`Job::unserialize()`: it must be a shared verify-then-unserialize helper that the broker drivers, the Worker (`Worker.php:70` serialises on failure), and the two queue Commands all call. `SerializationException` already exists in the queue package. **DI seam problem:** `Job::serialize()` is an instance method with no constructor (abstract base, no ctor) and `Job::unserialize()` is `static` returning `static` — neither can read a container-injected key. The signer key must be supplied by the caller (the queue driver / Worker / Command, which ARE container-managed and can be injected with the signer), NOT by `Job` itself. The plan below reflects this: introduce a `JobEnvelope` signer service in the queue package, inject it into the brokers/Worker/Commands, and have IT wrap/verify around the raw `serialize($job)`/`unserialize($payload)` — leaving `Job::serialize()`/`Job::unserialize()` as the raw inner serialization OR routing both through the envelope explicitly. There is NO `packages/queue/module.php` today; one must be created to bind the signer.
- Encryption: `EncryptorInterface` (`encrypt`/`decrypt`), `EncryptionConfig::key()` reads config key `encryption.key`. The `queue` and `cache-redis` packages do NOT yet depend on `marko/encryption`.

### Design decisions locked
1. **F1** — Add to `IdentifierValidator`: (a) `OPERATORS` allowlist const `['=', '!=', '<>', '<', '>', '<=', '>=', 'LIKE', 'NOT LIKE', 'IN', 'NOT IN', 'IS', 'IS NOT']` + `assertValidOperator(string): void` throwing `InvalidColumnException::invalidOperator()`; (b) `assertValidIdentifier(string): void` (loud wrapper over `isValidIdentifier`, also accepting the qualified `table.column` form) throwing `InvalidColumnException::invalidColumn()`; (c) `escapeDelimiter(string $part, string $delimiter): string` that doubles the delimiter. Drivers call these. `quoteIdentifier()` escapes the delimiter (`` ` `` →  ```` `` ````, `"` → `""`) per part. mysql and pgsql reach behavioral parity. **JSON-path carve-out (CRITICAL):** `where()`/`orWhere()` columns and SELECT/`orderBy` columns can legitimately be JSON-path expressions (e.g. `where('data->name', '=', 'Bob')` — a real, tested path that routes through `JsonPathParser::isJsonPath()` → `compileJsonExtract()`, NOT `quoteIdentifier()`). Identifier validation MUST be applied only on the non-JSON-path branch (inside the existing `else` of `JsonPathParser::isJsonPath($column)`), mirroring how the builders already gate quoting. A naive `assertValidIdentifier($column)` on every `where`/`orderBy` column will reject `->`/`->>` and break the existing JSON query-builder tests. `whereIn`/`whereNull`/`whereNotNull`/`join` columns and `table`/`count`/`insert`/`update` keys are plain identifiers and get full validation.
2. **F2** — Locked: `CacheInterface::increment(string $key, int $ttl): int` (atomic), implemented in `cache-array` (in-process), `cache-file` (flock), `cache-redis` (`INCR` + `EXPIRE`). `RateLimiter::attempt()` uses `increment()` instead of get→set. **IP resolution decision:** add a minimal `Request::server(string $key): ?string` + `Request::ip(): ?string` (returns `REMOTE_ADDR` — a server param, never a header) to `marko/routing`; the trusted-proxy logic lives in a new `ClientIpResolver` inside `marko/ratelimiter`, fed by `config/ratelimiter.php` (`trusted_proxies` default `[]`). It honors `X-Forwarded-For` only when `REMOTE_ADDR` is in `trusted_proxies`, and otherwise keys off `REMOTE_ADDR` — never the literal `'unknown'`. Rationale: routing stays generic (just exposes the request facts); proxy-trust policy belongs to the security-sensitive consumer.
3. **F3** — Validate `$locale`, `$group`, and `$namespace` against `^[A-Za-z0-9_-]+$` before path assembly in both branches; throw `TranslationException::invalidPathSegment()` (new factory) on violation.
4. **F4** — Reject (loud) any CR or LF in `Address::$name` (constructor) and in custom header name/value (`Message::header()`); add `MessageException::headerInjection()`. SmtpMailer is hardened defensively too (it must not be the only line of defense). Display names are NOT auto-encoded — we reject control chars, matching the existing "loud errors" posture; Subject keeps its existing `encodeHeader()`.
5. **F5** — `marko/routing`: `Request` gains immutable `withRoute(string $controller, string $action): self` and `controller()`/`action()` accessors (Request stays `readonly` — `withRoute` returns a clone). `Router::handle()` calls `$request = $request->withRoute(...)` before dispatching through the pipeline so every middleware sees route context. `AdminAuthMiddleware` reads `$request->controller()`/`$request->action()` instead of its constructor params (the now-unused `?string $controller`/`?string $action` ctor params are removed). Proven by: low-privilege admin denied (403) and properly-permissioned admin allowed on a `#[RequiresPermission]` route.
6. **F6** — Group by trust boundary. **Network brokers** (`cache-redis`, `queue` whose payload reaches the database/rabbitmq drivers): HMAC-SHA256-signed envelope (`hash_hmac` over the serialized bytes using the app key from `marko/encryption` config `encryption.key`; verify with `hash_equals` before `unserialize`; reject loudly on mismatch). For the queue, the signer is a `JobEnvelope` service in `marko/queue` injected into the broker drivers (`queue-database`, `queue-rabbitmq`), the `Worker`, and the two Commands — because `Job::serialize()` is a constructor-less instance method and `Job::unserialize()` is `static`, neither can read an injected key, so the envelope must be applied/verified by the container-managed callers that surround the raw (un)serialize. **Tier 1 therefore DOES edit `queue-database` and `queue-rabbitmq`** (their `unserialize()` at :120 each) plus the `Worker` serialize site (:70). **Local file backends** (`cache-file`, `page-cache-file`): use `unserialize($content, ['allowed_classes' => ...])`. The page cache stores only arrays of scalars/strings → `allowed_classes => false`. The general `cache-file` driver stores an arbitrary `mixed` value under the `value` key — consumers legitimately cache objects (an existing test stores a `stdClass` and asserts equality on read-back), so `allowed_classes => false` would BREAK that round-trip. For `cache-file`, allow the value to deserialize objects (the trust boundary is the local filesystem, an attacker with write access there already has code execution), OR — if a stricter posture is wanted — wrap the file cache value behind the same HMAC envelope; the locked Tier 1 decision is to keep object support and apply `allowed_classes => false` ONLY where objects are never stored (page-cache index/payload). The HMAC scheme is identical across `cache-redis` and `queue`: `hash_hmac('sha256', $serialized, $appKey)` + `hash_equals()`.

## Scope

### In Scope
- F1: operator allowlist + identifier validation + delimiter-escaping across both query-builder drivers and the shared `IdentifierValidator`.
- F2: `CacheInterface::increment()` across all three cache drivers; atomic `RateLimiter::attempt()`; trusted-proxy-aware client-IP resolution; `config/ratelimiter.php`; minimal `Request::server()`/`Request::ip()` accessors.
- F3: path-segment validation in `FileTranslationLoader` (both branches) + `TranslationException` factory.
- F4: CRLF rejection in `Address` name and `Message` custom headers + defensive hardening in `SmtpMailer::buildHeaders()` + `MessageException` factory.
- F5: route-context plumbing in `marko/routing` (`Request::withRoute`/accessors, `Router::handle` wiring) and enforcement in `AdminAuthMiddleware`.
- F6: HMAC envelope for `cache-redis` and the `queue` package (including the `queue-database` and `queue-rabbitmq` broker `unserialize()` sinks and the `Worker` serialize site, via a `JobEnvelope` signer service + new `packages/queue/module.php`); `allowed_classes => false` for `page-cache-file`; object-preserving hardening for `cache-file` (see design decision 6).

### Out of Scope
- Broader queue correctness (retry semantics, double-processing, broker driver *logic* edits) — Tier 2. NOTE: the broker drivers' bare `unserialize()` calls (`queue-database:120`, `queue-rabbitmq:120`) ARE in Tier 1 scope under F6 (verify-before-unserialize via the `JobEnvelope` signer); only their retry/double-processing logic is deferred to Tier 2.
- `selectRaw`/`whereRaw`/`orderByRaw`/`having` raw escape hatches — already hardened by the existing query-builder plan; untouched here.
- Sliding-window / token-bucket rate-limit algorithms; per-user limiting.
- RFC-2047 auto-encoding of display names (we reject control chars instead).
- Docs-site updates (`docs/src/content/docs/`) and README edits — handled by the post-implementation `doc-updater` agent per `.claude/pipeline.md`.
- Encryptor implementation changes — we only consume the app key.

## Architecture Notes
- All new exceptions use the three-part `MarkoException` shape (`message`, `context`, `suggestion`) with named args and static factory methods, matching `InvalidColumnException` / `MessageException`.
- **F1 static contract (task 001 → 002/003):** the three new `IdentifierValidator` methods (`assertValidOperator`, `assertValidIdentifier`, `escapeDelimiter`) MUST be `public static`, matching the entire existing static API (`isValidIdentifier`, `assertNoDangerousPatterns`, `parseSelectExpression`). The drivers call them statically (`IdentifierValidator::assertValidIdentifier(...)`) exactly as they already call `::assertNoDangerousPatterns(...)`. Instance methods would fatal the driver calls.
- **F2 atomic rewrite (task 007):** the existing `RateLimiterTest` suite must stay green. `tooManyAttempts()`/`clear()` stay read-only (never `increment()`); `remaining = max(0, maxAttempts - count)` where `count` is the value returned by `increment()`; `retryAfter` is read from the TTL via `getItem()`, never derived from the (growing) count.
- **F6 queue DI seams (task 014):** `DatabaseQueue`/`RabbitmqQueue` have defaulted `string` params and are bound via SIMPLE class-mapping bindings (verified — not closures), so adding `JobEnvelope` (a container-resolvable type) keeps them autowirable with no `module.php` change. The only hard rule is ordering: `JobEnvelope` MUST be placed BEFORE the defaulted `string` params (a required param cannot follow an optional one). `Worker` gains a required `JobEnvelope` param (autowired). `FailedCommand::extractJobClass()` already returns `'Unknown'` for real (object-serialized) payloads — there is no `$data['class']` array shape to preserve; just verify-then-unwrap before `@unserialize()`. Signer key in tests: seed `FakeConfigRepository(['encryption.key' => '<test-key>'])` since `EncryptionConfig::key()` throws `ConfigNotFoundException` when the key is absent from config and returns `''` only when `encryption.php` is loaded.
- Config defaults live ONLY in `config/*.php`; getters throw when missing (no hardcoded fallbacks). Env vars referenced only in config files.
- `declare(strict_types=1)`, constructor property promotion, full type declarations, no `final`, no magic methods, no traits, `readonly` where appropriate.
- `Request` stays `readonly`; `withRoute()` returns a cloned instance (immutability preserved).
- HMAC scheme (F6 network clusters): `hash_hmac('sha256', $serialized, $appKey)`, prepend `hex.payload` (or a small struct), verify with `hash_equals()` before `unserialize`. Identical scheme in both clusters per the locked design.
- File-cluster isolation: no two parallel tasks edit the same file. 002↔003 are different driver files; 006 is the sole owner of routing files. **Corrected:** task 005 edits `ArrayCacheDriver`, `FileCacheDriver`, AND `RedisCacheDriver` (adding `increment()`); task 012 also edits `FileCacheDriver` (allowed_classes) and task 013 also edits `RedisCacheDriver` (HMAC). To avoid two workers editing the same file, tasks 012 and 013 now depend on 005 (run after it). 014 (queue + brokers) is disjoint from the cache packages.
- `CacheInterface::increment()` (task 004) is a contract addition that breaks EVERY implementer, not just the three drivers. Known non-driver implementers: the two anonymous `CacheInterface` classes in `packages/health/tests/Unit/CacheHealthCheckTest.php` (lines 12, 88). Task 005 must add `increment()` to those test doubles too, or `marko/health`'s suite will fatal. Any future `FakeCache` in `marko/testing` would also need it.
- Atomic `increment()` TTL semantics (task 004/005): set the TTL ONLY on the first increment (when the key is created), do NOT reset the expiry on every subsequent increment. Resetting TTL on every call turns a fixed window into a never-closing window (a client under continuous load is locked out forever). Redis: use `SET key 1 EX ttl NX` then `INCR`, or `INCR` + `EXPIRE ... NX` (PHP-side: only `EXPIRE` when the returned value is 1). File/array drivers: only apply TTL when creating the counter.

## Risks & Mitigations
- **Risk: F1 breaks legitimate qualified identifiers / aggregates.** Mitigation: `assertValidIdentifier` accepts both plain and `table.column` qualified forms (mirroring existing `QUALIFIED_PATTERN`); `count()` `*`/null is handled explicitly; aggregate paths already validate via `isValidIdentifier`.
- **Risk: F2 IP resolution location bikeshed.** Mitigation: decision locked (routing exposes facts; ratelimiter owns proxy-trust policy) and recorded above; reduces routing surface area.
- **Risk: F5 `Request` immutability vs. mutation.** Mitigation: `withRoute()` clone keeps `readonly`; Router re-binds the local `$request` variable before the pipeline.
- **Risk: F6 HMAC needs an app key that may be empty in dev.** Mitigation: signer throws a loud exception when `encryption.key` is empty (no silent unsigned fallback); documented as a required env var.
- **Risk: F6 queue envelope collides with Tier 2 edits.** Mitigation: explicit sequential rebase note above — Tier 2 builds on Tier 1's envelope shape (including the broker `JobEnvelope` calls).
- **Risk: `Job::serialize()`/`unserialize()` cannot hold an injected key.** Mitigation: `serialize()` is a ctor-less instance method and `unserialize()` is `static`; the signer lives in a container-managed `JobEnvelope` service injected into the brokers/Worker/Commands, which wrap/verify around the raw (un)serialize. `Job` is not given a DI dependency.
- **Risk: F6 broker `unserialize()` sinks left unprotected.** Mitigation: corrected scope — `queue-database:120` and `queue-rabbitmq:120` are hardened in task 014 (they were mis-classified as no-op pass-throughs in the original draft).
- **Risk: `allowed_classes => false` breaks legitimately cached objects in `cache-file`.** Mitigation: keep object support in the general file cache (filesystem-write trust boundary = already RCE); apply `allowed_classes => false` only to `page-cache-file`, which stores no objects. Existing `it('sets and gets object value')` test must keep passing.
- **Risk: `CacheInterface::increment()` breaks other implementers.** Mitigation: task 005 also updates the `marko/health` test doubles that implement `CacheInterface`.
- **Risk: F1 identifier validation breaks JSON-path `where`/`orderBy`.** Mitigation: validate only on the non-JSON-path branch (mirror existing `JsonPathParser::isJsonPath()` gating); JSON-path tests must keep passing.
- **Risk: adding `marko/encryption` dependency to `queue`/`cache-redis` creates a cycle.** Mitigation: `encryption` depends only on `core`/`config`, not on queue or cache, so the dependency is acyclic; verified Phase 1.
