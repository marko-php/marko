# Plan: devai Overridable, Portable Guideline Files

## Created

## Objective
Make `marko/devai` generate AI agent guideline files that are portable across tools, single-sourced, and fully user-overridable — never clobbering user edits, never shipping dead links, and never leaking Claude-Code-specific paths into tool-agnostic files.

## Discovery Notes
Verified across all six agents (`packages/devai/src/Agents/*`) and the renderer:

- **Inconsistent AGENTS.md handling today.** `ClaudeCodeAgent` and `CodexAgent` clobber `AGENTS.md` unconditionally; `Copilot`/`Junie`/`Cursor`/`Gemini` write it only if absent but always clobber their own tool file (`.github/copilot-instructions.md`, `junie/guidelines.md`, `.cursor/rules/marko.mdc`, `GEMINI.md`) with the full body duplicated.
- **No partial/marker regeneration exists** — a user-edited file is either clobbered or never updated. The marker mechanism introduces the missing middle ground.
- **The body is rendered once** by `AgentsMdRenderer::render()` (the "Generated by marko/devai…" header is emitted at line 29) and shared via `ctx->guidelines` (a `GuidelinesContent` value object: `body`, `filename`).
- **The dead-link leak:** `packages/devai/resources/ai/guidelines/core.md` hardcodes a `## See Also` block pointing to `.claude/architecture.md`, `.claude/testing.md`, `.claude/code-standards.md`. Those files exist only in the Marko monorepo, never in a generated project (verified: acta's `.claude/` holds only `settings.json`). `.claude/` is also Claude-Code-specific and must not appear in the tool-agnostic AGENTS.md.
- **Static-helper precedent:** `SkillsDistributor::syncBundles()` is a static filesystem-sync helper already called by multiple agents — `GuidelinesWriter` follows the same pattern (no DI/constructor wiring needed across agents).

**Resolved design decisions (from clarification):**
1. **Marker discipline reaches ALL generated files** (root `AGENTS.md`/`CLAUDE.md`/`GEMINI.md` AND tool-dir files). One shared writer, uniform behavior across all six agents.
2. **No static reference docs shipped.** Depth is already served by the cross-tool `marko-mcp` `search_docs` (devai registers the MCP for all six tools) and `marko-lsp` diagnostics. Shipping `.agents/references/*.md` would re-introduce a drifting parallel source. The baseline standards stay **inline** in AGENTS.md via `core.md`. `hcf-marko` remains the future, opt-in home for *process* opinions only.
3. **`.agents/` (plural)** is the portable convention; `.claude/` is reserved for Claude-Code-specific artifacts only.
4. **Inline guidelines = "Bucket B" only** — behavior-shaping, non-lintable, consumer-relevant rules that shape default output and that neither the LSP (can't express) nor an un-invoked MCP (pull-based) supplies proactively. Three control layers, three jobs: inline AGENTS.md = proactive prior (prevention); `marko-lsp` = post-hoc structural enforcement of the lintable subset (detection); `search_docs` MCP = on-demand depth (retrieval). The monorepo's `code-standards.md` (459 lines) is mostly tooling-auto-fixed or framework-contributor content — NOT shipped. `core.md` is curated to Bucket B and gains four missing rules (no-traits, interface-over-driver, constructor-injection, config-as-truth). See task 002.
5. **Docs-coverage audit (task 000, pre-checked):** the `search_docs` corpus (`packages/docs-markdown/docs/`) already covers every Bucket-C concept (modularity, DI, plugins, events, preferences, a 279-line custom-module tutorial, getting-started, per-package guides). Content gap risk is low; the open risk is retrieval *ranking* for natural greenfield phrasings — task 000 validates this against the live MCP before we fully commit to leaning on it.

## Scope

### In Scope
- New `GuidelinesWriter` static helper implementing marker-aware writes: create-if-absent, replace-only-between-markers, back-off-untouched-if-markers-absent (loud notice).
- Marker constants/format: `<!-- BEGIN marko:devai -->` … `<!-- END marko:devai -->`, BEGIN carrying do-not-edit-between-markers semantics + `marko devai:update` hint + "content outside is yours" note.
- Route every guideline/instruction file write in all six agents through `GuidelinesWriter` (AGENTS.md + each agent's tool-specific file; CLAUDE.md's marker region wraps the `@AGENTS.md` import + Claude tooling block).
- `AgentsMdRenderer`: hand off the standalone "Generated…" header to the writer's marker so the two don't double up.
- `core.md`: remove the `.claude/` `## See Also` block; replace with a cross-tool `search_docs` (MCP) pointer.
- Tests: unit tests for `GuidelinesWriter`, per-agent write-behavior tests, and updated integration tests (monorepo + external project).
- devai package docs/README refresh reflecting the new override behavior.

### Out of Scope
- The `hcf-marko` plugin (future home for TDD/PR-process/workflow opinions). Baseline correctness rules stay in devai.
- Shipping any static `.agents/references/*.md` reference docs.
- MCP/LSP registration logic and `.claude/settings.json` merge behavior — unchanged; must not regress.
- Switching tool files to import-based dedup (e.g. `GEMINI.md` importing `@AGENTS.md`) — body duplication stays, now marker-managed.

## Architecture Notes
- `GuidelinesWriter` is a **static helper** mirroring `SkillsDistributor::syncBundles()` — no per-agent constructor/DI changes. Signature shape: `GuidelinesWriter::write(string $path, string $generated, string $label = 'marko:devai'): WriteOutcome` returning the `Marko\DevAi\Writing\WriteOutcome` enum (`Created`|`Updated`|`SkippedNoMarkers`) so callers/tests can assert.
- **Notice surfacing.** `AgentInterface::install()` returns `void` and agents hold no `Output`, so there is no return-value channel for the "loud notice on skip". `GuidelinesWriter` therefore keeps a static notice buffer: it appends a message on every `SkippedNoMarkers` return, exposed via `GuidelinesWriter::takeNotices()` (returns + clears). The orchestrator drains it after the agent loop and appends to `$this->log` (task 010), so the install/update command prints it. The writer itself never echoes — it stays pure/testable.
- **Cursor `.mdc` frontmatter.** YAML frontmatter `---` must be the first byte of the file; a leading `<!-- BEGIN -->` would break Cursor's rule parser. Markers wrap only the body BELOW the frontmatter; the frontmatter is treated as user-side "content outside markers" (task 006).
- **Multi-agent shared AGENTS.md.** The orchestrator runs every selected agent against the same root `AGENTS.md`. First agent creates it (with markers); the rest perform idempotent in-marker updates. Net result: exactly one marker pair regardless of agent count (asserted in task 010).
- Marker semantics live in one place (constants on `GuidelinesWriter`) so all agents and the renderer agree.
- `CLAUDE.md` is the one file whose marker region wraps non-body content (`@AGENTS.md` import + Claude tooling block) rather than the rendered guideline body. The writer is content-agnostic — it wraps whatever generated string it's given.
- Tool files duplicate the body (Copilot/Cursor/Junie can't import); duplication is acceptable because it's now marker-synced. Cross-tool single-source remains AGENTS.md; tool files are projections.
- Follow Marko core principles: loud errors (notice on skip), explicit over implicit (markers are visible), everything overridable.

## Risks & Mitigations
- **Regressing MCP/LSP registration**: keep all `registerMcpServer`/settings/LSP code paths untouched; only swap the `file_put_contents` guideline writes. Existing MCP tests guard this.
- **`.cursor/rules/marko.mdc` has YAML frontmatter**: markers wrap ONLY the body; the `---` frontmatter must remain the first line of the file (a leading HTML comment breaks Cursor's parser). Frontmatter is preserved as "content outside markers". Explicit test in task 006 asserts the first line is `---`.
- **Idempotency / double markers**: writer must detect existing markers and replace between them, not append a second pair; a BEGIN-without-END (malformed) file is treated as skip-no-markers and left untouched. Covered by dedicated `GuidelinesWriter` tests (task 001) and a multi-agent single-marker-pair assertion (task 010).
- **Header duplication**: removing the renderer header (task 003) must land before/with agent tasks so output isn't double-stamped. The specific failing renderer assertion (`AgentsMdRendererTest` lines 66–70) is named in task 003. Encoded as a dependency.
- **Notice has no consumer**: the writer's skip notice is invisible unless the orchestrator drains `takeNotices()` — wired and tested in task 010, depends on task 001.
- **Breaking exact-equality test assertions**: every agent test currently asserts guideline file content with `->toBe('<body>')`; marker-wrapping breaks byte equality. Each agent task (004–009) names the exact line(s) to convert to `->toContain(...)` + marker-presence, and re-targets the former "only-if-absent" assertions to the new "marker-strip back-off" semantics.
